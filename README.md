# QueryLens

Настольное приложение для анализа SQL-запросов PostgreSQL. Проверки используют
структуру SQL, JSON-план и метаданные базы. Результат содержит краткое пояснение,
место в запросе и рекомендуемое действие. Для работы не нужны LLM и Ollama.

## Установка и запуск

Нужен Python 3.12. Создайте окружение и установите зависимости:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_querylens.py --check
.venv/bin/python run_querylens.py
```

На Windows в PowerShell:

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe run_querylens.py --check
& .\.venv\Scripts\python.exe run_querylens.py
```

Если окружение уже создано, достаточно последней команды с его интерпретатором.
Проверка `--check` не подключается к базе. Подробности: [установка](docs/installation.md).

## Работа с приложением

1. Подключитесь к локальной PostgreSQL через плашку подключения.
2. Введите SELECT. Выделенный текст имеет приоритет; иначе анализируется запрос под курсором.
3. Нажмите «Анализировать» или Ctrl+Enter.
4. Прочитайте вкладку «Кратко». План, исходные показатели и ограничения доступны
   во вкладках «Подробности» и «JSON».

По умолчанию используется EXPLAIN без выполнения запроса. Опция «Измерить
(ANALYZE)» действительно выполняет SELECT в транзакции только для чтения с
тайм-аутом. Во время анализа доступны отмена и ограничение времени SQL.
Предложенный вариант SQL не выполняется автоматически.

Подключение ограничено адресами localhost, 127.0.0.1 и ::1. Имена таблиц и схем
получаются из PostgreSQL: анализ не привязан к демонстрационной базе bookings.
Это не означает проверенную совместимость со всеми версиями PostgreSQL.

## Проверки SQL

| Код | Конструкция |
| --- | --- |
| AP01 | SELECT * и alias.* |
| AP02 | Функции, вычисления и приведения столбцов в WHERE |
| AP03 | LIKE/ILIKE с начальным % |
| AP04 | Условия OR |
| AP05 | NOT IN и значения NULL |
| AP06 | DISTINCT |
| AP07 | Сортировки |
| AP08 | Пагинация с OFFSET |
| AP09 | Условия HAVING |
| AP10 | N+1: проверка достаточности контекста приложения |
| AP11 | COUNT для проверки существования |
| AP12 | Декартово произведение |
| AP13 | CTE |
| AP14 | Оконные функции |
| AP15 | Соединения JOIN |

Наличие конструкции не доказывает замедление. Например, обычный Seq Scan или
JOIN может быть эффективным, а COUNT(*) не считается SELECT *. Для N+1 нужен
контекст одной операции приложения; по одному SQL такой вывод не делается.
Без требований к результату нельзя определить лишние столбцы SELECT *.

## Дополнительные возможности

- «Анализ БД»: конфигурация, таблицы, столбцы, индексы, ограничения и статистика.
- «Ресурсы»: графики CPU, памяти и дискового ввода-вывода компьютера приложения.
- История SQL с поиском, открытием сохранённых результатов и удалением записей.
- Экспорт диагностического примера в JSONL кнопкой «В датасет».
- Отдельные инструменты ручной разметки и проверки качества правил.

Показатели компьютера не являются измерением ресурсов конкретного SQL и не
доказывают ограничение сервера PostgreSQL. Настройки диагностической сессии
могут отличаться от настроек приложения, из которого был взят запрос.

История хранится в `history.sqlite3` в каталоге Qt AppLocalDataLocation.
Параметры интерфейса сохраняются через QSettings. Экспорт содержит исходный SQL,
его литералы и метаданные без обезличивания; пароль подключения в него не входит.
Подключение к серверу генерации текста и автоматическое скачивание моделей отсутствуют.

## Структура проекта

- `app/analyzers/` — признаки SQL, анализ плана и 15 проверок.
- `app/collectors/` — сведения PostgreSQL и показатели ОС.
- `app/services/` — анализ, отчёты, экспорт и сравнение запросов.
- `app/controllers/` — управление действиями и ресурсами приложения.
- `app/workers/` — фоновые задачи.
- `app/ui/` — окна, редактор, графики и оформление.
- `app/storage/` — история и настройки.
- `scripts/` — команды проверки и работы с примерами.
- `tests/` — автоматические проверки и SQL-набор.

## Проверка

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты PostgreSQL запускаются отдельно в тестовой базе. Команда
`python scripts/check_all_rules.py --execute` создаёт или использует отдельную
базу `querylens_test_validation`; перед запуском прочитайте
[описание стенда](docs/sql_test_matrix.md).

На Mac с PostgreSQL 18.4 пользовательский запуск проверил 128 SQL-сценариев без
ошибок; ещё 3 не выполнялись без значений параметров. Это регрессионный набор,
а не независимая оценка точности всех рекомендаций. Проверку GUI на Windows и
поддерживаемые версии PostgreSQL нужно фиксировать отдельно.
