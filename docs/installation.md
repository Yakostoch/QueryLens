# Установка и запуск QueryLens

Актуальная копия проекта должна включать все применённые обновления. Ветка main на GitHub не получает локальные патчи автоматически. Не заменяйте рабочую копию более старым архивом или клоном main без переноса изменений.

Приложение использует Python, PySide6, psycopg, psutil и SQLGlot. Диапазоны зависимостей записаны в requirements.txt. Для воспроизводимого окружения рекомендуется Python 3.12. Проверка зависимостей не заменяет проверку работы GUI на нужной ОС.

## macOS: существующее окружение

```bash
cd "$HOME/Desktop/QueryLens-updated"
"$HOME/QueryLensEnv/bin/python" run_querylens.py --check
"$HOME/QueryLensEnv/bin/python" run_querylens.py
```

Последняя команда открывает приложение. Ручная длинная команда env -u больше не требуется: запускатель очищает конфликтующие настройки Qt только для дочернего процесса. Глобальные настройки терминала не меняются. По умолчанию используется системный шрифт интерфейса, без требования установленного Segoe UI.

## Windows: новое окружение в PowerShell

Перенесите актуальные исходники проекта на Acer в папку QueryLens-updated на рабочем столе. Виртуальные окружения QueryLensEnv, .venv и .venv-clean с Mac не переносите: их нужно создавать на целевой ОС. Если рабочий стол находится в OneDrive или папка названа иначе, замените путь в первой команде на фактический.

Установите Python 3.12, если его ещё нет. В PowerShell:

```powershell
cd "$HOME\Desktop\QueryLens-updated"
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe run_querylens.py --check
& .\.venv\Scripts\python.exe run_querylens.py
```

Активировать окружение не требуется. Если команда py не найдена, проверьте установку Python и доступность его запускателя. При ошибке установки зависимостей или проверке окружения сначала исправьте её; успешный импорт ещё не подтверждает отображение окна на Windows.

Для SQL-анализа на Windows нужна доступная локальная PostgreSQL с базой и ролью. Открытие GUI можно проверить без БД. Текущая версия подключения разрешает только localhost/127.0.0.1/::1; подключение к удалённому серверу этим обновлением не добавлено.

## Что делает --check

- Проверяет наличие пакетов и их диапазоны версий из текущих требований.
- Проверяет импорт приложения и зависимостей в отдельном процессе.
- Создаёт только QApplication в offscreen-режиме, чтобы проверить загрузку Qt без рабочего окна.
- Не подключается к PostgreSQL, не выполняет SQL и не открывает историю приложения.

Проверка не устанавливает пакеты автоматически и не проверяет отображение реального рабочего окна, драйвер видеокарты или работу с PostgreSQL на этой ОС. Системный шрифт проверяется при запуске рабочего приложения.

## Проверка GUI на целевой ОС

После запуска проверьте размер окна, читаемость SQL и краткого вывода, переключение SQL / Анализ БД / Ресурсы, поиск и открытие истории. После подключения к своей локальной PostgreSQL выполните простой SELECT, затем запрос с ошибкой и снова корректный запрос. Для ANALYZE отдельно проверьте тайм-аут и отмену известного вам запроса.

Сохранение 128 успешных SQL-сценариев на PostgreSQL 18.4/macOS не заменяет этот запуск на Windows. До фактической проверки Acer Windows остаётся неподтверждённой целевой платформой.

## Фактические результаты и оставшиеся части

На компьютере пользователя PostgreSQL 18.4/Homebrew/macOS: 128 исполняемых сценариев авторского набора прошли, 0 ошибок, 3 случая с неизвестными параметрами не исполнялись. Это регрессионная проверка, а не независимая оценка точности диагноза.

Для DISTINCT по первичному ключу медианы составили 4,52 и 2,21 мс; для COUNT(*) > 0 / EXISTS — 0,04 и 0,02 мс. Проверено совпадение результатов на текущих данных. Эти наблюдения не гарантируют ускорение на других данных и нагрузках.

Диагностика основана на правилах и фактах SQL/плана/метаданных. LLM и Ollama не требуются. Настройки компьютера клиента не означают измерение ресурсов сервера PostgreSQL. Для сдачи нужно отдельно указать фактически проверенные ОС и версии, границы анализа.
