# Устройство анализа QueryLens

## Путь запроса

SQL-редактор → фоновая задача → PostgreSQL EXPLAIN → метаданные → проверки → отчёт.
Синтаксис разбирается SQLGlot; имена объектов разрешаются через каталоги PostgreSQL.
Выполнение SELECT включается только опцией ANALYZE. Приложение не меняет
конфигурацию базы и не выполняет предложенные исправления автоматически.

## Данные проверки

- Исходный SQL и доступные значения параметров.
- Полный JSON-план, режим EXPLAIN и сведения о сервере.
- Стоимость, строки и ширина корня; расчётный объём результата.
- Узлы плана и признаки конкретной конструкции SQL.
- Столбцы, типы, индексы, ограничения и доступная статистика объектов запроса.
- Явные требования к результату, если они известны.

Недоступные сведения отмечаются отдельно. Ошибка чтения метаданных не означает
отсутствие индекса. Стоимость плана не является временем, а ширина результата
не равна объёму прочитанных данных или памяти операции.

## Результат

Во вкладке «Кратко» показываются до трёх полезных замечаний: где найдено,
почему это заслуживает проверки и что сделать. Подробные факты и ограничения
доступны отдельно. Нормальная операция плана сама по себе не становится
предупреждением. Без данных для вывода программа указывает ограничение.

Пояснения формируются программой по результатам правил. Вызовов LLM нет.
Сборщики настроек и ресурсов помогают получить контекст, но сами по себе не
устанавливают причину задержки SQL.

## Проверка результата

Автоматические тесты проверяют анализаторы, интерфейс, отмену, историю и экспорт.
SQL-набор запускается в отдельной PostgreSQL с откатом тестовых схем и данных.
Парные эксперименты проверяют результаты двух выбранных SELECT и чередуют
измерения. Независимая оценка качества правил проводится отдельно от регрессии.

Актуальные задачи перечислены в [плане завершения](completion_plan.md).
Документы с суффиксами step1–step16 описывают предыдущие этапы и могут содержать
исторические планы, которые больше не входят в текущий объём работы.
