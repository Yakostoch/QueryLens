# Этап 4 — JOIN и независимость от структуры PostgreSQL

База: установленный этап QueryLens_access_step3. Интерфейс и зависимости сохранены.

## Что изменено

1. Сборщик структуры сохраняет source_bindings: область SELECT, псевдоним,
   схема, имя и OID отношения, разрешённого самим PostgreSQL через to_regclass.
   В анализаторе нет предположения, что таблицы находятся в public.
2. AP02/AP03 сопоставляются с отдельным источником одного SELECT с прямыми JOIN.
   Поиск узла требует совпадения схемы, отношения и псевдонима. Самосоединение
   не позволяет приписать фильтр второго экземпляра первому.
3. Неуточнённое имя столбца разрешается только при единственном допустимом источнике.
   Выражение, зависящее от нескольких таблиц, или неоднозначное имя дают unknown.
4. AP12 использует граф источников каждой области SELECT. Учитываются ON и WHERE,
   логические AND/OR и простой USING двух источников. Связанный JOIN не выводится
   как кандидат декартова произведения. Сравнение может быть неравенством — не
   требуется выдумывать FK или угадывать связь по похожим именам столбцов.
5. Для независимых источников остаётся кандидат AP12, а не утверждение ошибки:
   CROSS JOIN может быть намеренным. Если смысл связи не установлен, статус unknown.
6. В текстовом отчёте выводится состояние связей источников. AP15 назван
   «JOIN: проверка эффективности», чтобы конструкция не выглядела готовым диагнозом.

## Проверка на разных структурах

- 200 автоматических тестов: 199 успешно, один opt-in native PostgreSQL пропущен.
- Основной SQL-корпус расширен с 68 до 76 примеров, все 15 сценариев сохранены.
- 74 запроса получили EXPLAIN и выполнены через EXPLAIN ANALYZE BUFFERS в PGlite
  PostgreSQL 18.6 / PGlite 0.5.12 (WASM), два параметризованных случая проверены по AST.
- Проверены две схемы с одинаковым именем Records, пробелы и регистр в кавычках,
  кириллические столбцы и таблицы, самосоединение, LEFT JOIN, USING и comma join.
- Для неуточнённого Records выбор через search_path отличается от явного источника
  второй схемы; оба источника привязаны правильно через каталог.
- В unit-тестах дополнительно проверены 20 воспроизводимо сгенерированных наборов
  имён схем/таблиц/столбцов и неоднозначные/многотабличные выражения.
- В SQL-прогоне метаданные доступны для 73 запросов. Для одного рекурсивного CTE
  ожидаемо недоступен сбор структуры; его SQL и план при этом получены.

Это не обещание поддержки каждого синтаксиса и каждой версии PostgreSQL.
Цель — отсутствие привязки к предметной области и демонстрационной базе.
Код подключения остаётся в прежнем локальном режиме loopback. Удалённые подключения
этот патч не добавляет. Возможности чтения метаданных зависят от прав роли.
Ограничения доступности отмечаются явно, а не подменяются отсутствием индексов.

## Ограничения текущего анализа

- Поддержан один SELECT с прямыми таблицами/материализованными представлениями.
  CTE, вложенные SELECT, обычные представления и секционированные родители
  требуют дополнительной привязки; исходный план при этом сохраняется.
- Сопоставляются простые сравнения в WHERE с AND. OR, NOT, преобразованный или
  исчезнувший предикат, условие на нескольких источниках приводят к unknown.
- Граф AP12 не выдаёт ложную связь из одной произвольной ветви OR. Для NATURAL,
  многосоставного USING, LATERAL и неизвестной lineage предусмотрено воздержание.
- Связный граф не доказывает полную связь составного ключа, правильную кратность,
  быстрое выполнение JOIN или намерение пользователя.
- Состояние connected описывает связи в SQL. Физический способ соединения остаётся
  в исходном плане; граф не заменяет разбор Hash Cond / Join Filter и статистику исполнения.
- Обычный EXPLAIN приложения не выполняет запрос через ANALYZE. Фактическое выполнение
  предусмотрено только отдельным тестовым scripts/run_sql_lab.py в querylens_test*.
- WASM SQL-прогон не проверяет psycopg wire protocol и не является бенчмарком native
  PostgreSQL. Результаты не означают, что реализована диагностика всех 15 причин.

## Применение и проверка

Патч накладывается поверх третьего этапа, без переключения ветки и восстановления stash.
Полная инструкция — README архива. Новых пакетов приложения нет.

Матрица и SQL: docs/sql_test_matrix.md, tests/fixtures/sql_cases.json.
Отдельный прогон в заранее созданной тестовой базе:

```bash
"$HOME/QueryLensEnv/bin/python" scripts/run_sql_lab.py --database querylens_test_lab --user ИМЯ_РОЛИ
```

Используется только отдельная querylens_test*; не demo. Новые схемы и данные,
измерения и ANALYZE откатываются общей транзакцией. Существующие схемы не удаляются:
создание с занятым именем прерывает подготовку. С --with-trigram требуются pg_trgm
и права на его использование/установку. Время одного прогона не доказывает ускорение.

## Следующий этап

Правила SELECT *, OFFSET и COUNT с контрактом потребителя; затем OR/NOT IN,
DISTINCT и прочие группы. Привязка к областям CTE/подзапросов расширяется отдельно.
Новые ошибки пополняют контрольный набор. Синтаксические кандидаты не становятся
положительными обучающими метками причин замедления автоматически.
