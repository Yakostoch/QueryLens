# Этап 10: краткий результат анализа

Основная вкладка «Кратко» показывает не более трёх замечаний: часть запроса,
краткое объяснение и действие. Порядок берётся из дерева диагностики, без новых
порогов cost и без предположений LLM. Доказанная лишняя операция не объявляется
доказанной причиной задержки. Измеренное время показывается отдельно.

«Подробности» содержит прежний полный текстовый отчёт. «JSON» сохраняет исходный
диагностический пакет, включая план. «Вариант SQL» появляется только при наличии
кандидата, подготовленного существующим анализатором. Это ручная проверка,
автоматического выполнения или подстановки в редактор нет.

Отсутствие сведений обрабатывается явно. SELECT * без требований к полям не
объявляется лишней выборкой. NOT IN без гарантий NULL не заменяется автоматически.
Наличие обычного JOIN, Sort, WindowAgg или CTE само по себе не порождает замечание
на главной вкладке. Соответствующие проверки остаются в подробностях. Предупреждение
N+1 не повторяется для одиночного SQL: нужна трасса операции приложения.

Если замечаний нет, результат говорит: «По доступным данным конкретных проблем
не выявлено. Это не гарантирует оптимальность запроса». Это результат ограниченных
проверок, а не сертификат оптимальности.

История продолжает хранить полный исходный отчёт. При открытии сохранённых
отчётов с diagnostic_tree краткий вывод строится заново. Для старого или
повреждённого формата доступен первоначальный текст в подробностях. Изменение SQL,
новый анализ, ошибка и отмена очищают все представления, включая вариант SQL.

Изменение касается представления результата: сбор метаданных, выполнение SQL,
правила диагностики и политика подключения не меняются. Проверка произвольных
схем использует ранее собранный корпус; полная совместимость со всеми версиями
PostgreSQL этой правкой не заявляется.

## Проверка

Автоматические тесты проверяют первичный ключ / DISTINCT, COUNT / EXISTS,
SELECT *, NULL, независимые таблицы, хорошие запросы, измеренную сортировку,
ограничение тремя замечаниями, старую историю и очистку вкладок. Дополнительно
краткий вывод воспроизведён для 128 сохранённых результатов SQL-корпуса; три
параметризованных случая без успешного исходного выполнения пропущены. Это
повторная обработка ранее собранных планов, а не новое выполнение SQL на сервере.

Этот пакет завершает часть этапа 10 по интерфейсу. Экспорт размечаемого датасета
и последующее обучение модели в него не входят и не считаются выполненными.
