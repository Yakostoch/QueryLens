# Этап 8: измерения и сравнение

Патч поверх этапа 7, без новых зависимостей. Изменения общие для macOS и Windows, однако native-запуски этих ОС здесь не выполнены.

## Два режима

По умолчанию остаётся EXPLAIN без ANALYZE. Флажок «Измерить (ANALYZE)» включает выполнение одного выбранного SELECT; перед каждым запуском интерфейс требует подтверждения, по умолчанию выбрана отмена. Поддерживаемый SQL по-прежнему ограничен одним SELECT/объединением SELECT без DML, SELECT INTO и блокировки строк.

Используется EXPLAIN (ANALYZE, BUFFERS, VERBOSE, TIMING, SUMMARY, FORMAT JSON). На свежей диагностической транзакции предварительно выполняются SET TRANSACTION READ ONLY и локальные statement_timeout/lock_timeout. Если подготовка режима завершается ошибкой, SELECT не выполняется. Лимит SQL по умолчанию 5 секунд, в интерфейсе 1–30 секунд; lock_timeout не больше 1 секунды. Это лимит отдельного SQL на сервере, не всей процедуры подключения и сбора метаданных.

ANALYZE выполняет запрос и добавляет накладные расходы. READ ONLY не является песочницей для произвольных функций и не отменяет эффекты вне базы. Поэтому согласие относится к конкретному выбранному SQL и не переносится автоматически на сгенерированный кандидат.

## Отмена

Кнопка «Отменить» устанавливает флаг рабочего потока и отправляет cancel_safe(timeout=1) текущему psycopg-соединению из отдельного фонового потока. GUI не ждёт сетевого обмена отмены. Соединение привязано только к одному запуску и отвязывается при выходе. При закрытии окна используется тот же путь. Серверный тайм-аут является отдельным ограничением; отмена не объявляется мгновенной или гарантированной при сбое соединения.

После отмены/тайм-аута не сохраняется успешный отчёт или незавершённый замер. Сообщения ошибок не содержат SQL драйвера, пароль или параметры подключения. Полученный, но ещё не обработанный результат также игнорируется после запроса отмены.

## Метрики

В JSON добавлен runtime_analysis. Execution Time и Planning Time берутся из верхнего уровня исходного JSON. Для узлов сохранены Actual Rows, Actual Loops, Actual Startup/Total Time, счётчики удалённых строк, буферы, временные блоки, I/O-время при доступности, Heap Fetches, хеш-batches, поля сортировки и сведения workers. Отсутствующее значение остаётся неизвестным, а не нулём. Исходный JSON сохранён полностью, включая неизвестные будущие поля PostgreSQL.

Actual Rows и Rows Removed являются средними на цикл. Приблизительное произведение rows × loops не является числом уникальных строк и может отражать округление. Буферы уже учитывают повторные обращения и дочерние операции: их не умножаем на loops и не суммируем между родителем и потомком. Shared Read не объявляется физическим чтением накопителя.

Для сортировки Disk показывается измеренное использование диска. Temp Read/Written Blocks показывают временный I/O, но не единственную причину. Несколько batches — отдельное наблюдение, а не автоматическое предложение увеличить work_mem. Данные отдельных workers сохранены отдельно и не прибавляются к общим значениям. Сведения Incremental Sort сохраняются без выдуманной интерпретации.

Отношение оценки строк к наблюдению является описательным, не диагнозом. Оно подавляется для планов с LIMIT, параллелизмом, semi/anti join, SubPlan/InitPlan и Run Condition; неисполненные узлы имеют отдельный статус. Совместное время узлов не складывается и не считается чистым временем операции.

## Сравнение двух SQL

scripts/compare_queries.py запускает только два явно переданных файла SQL при обязательном --execute. Автоматический выбор или выполнение кандидата из рекомендаций отсутствует. За раунд выполняются оба запроса; порядок чередуется AB, BA, AB. Каждый замер получает отдельное диагностическое соединение и READ ONLY, одинаковые заданные лимиты. Указываются все значения и медианы по 1–5 повторам каждого запроса.

Сохраняется ограниченный снимок сессии: база, роль, версия, search_path, часовой пояс, work_mem, jit, параллелизм, READ ONLY. При различии снимков отношение медиан не публикуется. Это не полный контроль окружения: нагрузка, кеш, статистика и данные могут меняться. Кеш не сбрасывается. Равенство результатов не проверяется и не выводится из совпадения числа строк. Измеряется серверное выполнение под EXPLAIN, а не подключение или передача результата приложению. Отчёт содержит SQL и остаётся локальным; пароль в JSON не включается.

## Проверка и ограничения среды

Полный набор: 351 тест, 347 успешных, 4 native-интеграционных пропущены без отдельного PostgreSQL. Новые проверки покрывают UI-подтверждение, отмену без сохранения истории, подготовку READ ONLY/тайм-аутов до SELECT, очистку параметров, ошибки без утечки текста, усреднение loops, буферы, workers, Disk Sort, HashAgg batches, чередование сравнений и различие настроек.

SQL-корпус прежних этапов: 131 сценарий, 128 проверены PostgreSQL 18.6 в PGlite 0.5.12, три — синтаксически. Дополнительно на PGlite прошли 6 измеренных сценариев: полный сервис SELECT, COUNT, LIMIT, сортировка с диском, запрет записи через функцию и повторное сравнение. Ещё одна проверка — statement_timeout — не подтвердилась в PGlite и записана как unavailable, не как успешная. Это наблюдение конкретной среды, не доказательство отсутствия тайм-аута в native PostgreSQL.

В тестовом HTTP-адаптере нет native libpq cancel_safe. Реальная отмена и тайм-аут требуют отдельного запуска tests/test_measured_postgres.py с QUERYLENS_TEST_DATABASE=querylens_test*. Они не объявляются проверенными через WASM или mocks. В приложении используется native psycopg пользователя; никаких зависимостей PGlite в продукте нет.

Документация PostgreSQL: https://www.postgresql.org/docs/18/sql-explain.html и https://www.postgresql.org/docs/current/using-explain.html. Эти источники описывают выполнение ANALYZE, накладные расходы, средние значения loops и включающие дочерние операции счётчики буферов.
