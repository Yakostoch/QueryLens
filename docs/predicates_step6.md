# Этап 6: OR и NOT IN

Изменение поверх этапа 5. Интерфейс, формат истории и режим EXPLAIN без ANALYZE сохранены. Дополнительные зависимости не нужны.

## AP04: OR

Анализатор сохраняет логическую группу и окружающие AND. Для прямого источника внешнего WHERE сопоставляет предикат с Filter, Index Cond и Recheck Cond. Индексные ветви связываются с BitmapOr только при совпадении всей группы и отдельном сопоставлении каждой ветви с дочерним потоком. Чужой BitmapOr не засчитывается. Ключи индексов по каталогу являются кандидатами, а не доказательством применимости. OR в проекции не считается проблемой фильтрации.

Равенства одного столбца константам могут получить вариант выражения IN без обещания ускорения. UNION и UNION ALL не генерируются: пересечения и кратность не доказаны. Для разных таблиц, ON, вложенных источников и неоднозначного сопоставления возвращается недостаточность данных.

## AP05: NOT IN

Проверяются обе стороны сравнения. Отсутствие NULL устанавливается по валидированным ограничениям либо явному положительному IS NOT NULL, а не по null_frac. Для PostgreSQL до 18 учитывается флаг NOT NULL столбца; без версии и доказательств результат остаётся неизвестным. Невалидированное NOT NULL не является достаточным основанием.

Кандидат NOT EXISTS создаётся только для узкого случая: внешнее положительное условие WHERE, два простых SELECT по физическим обычным таблицам, некоррелированный подзапрос, ненулевые прямые столбцы одинаковых поддержанных базовых типов, известное отсутствие RLS. Исключены LIMIT, агрегация, DISTINCT, сортировка и функции внутри подзапроса, CTE и другие неподдержанные формы. Внутренний псевдоним переименовывается, чтобы не захватить одноимённую внешнюю ссылку.

Кандидат требует проверки операторов, прав доступа, результата и измерений; приложение его не выполняет. Отсутствие NULL само по себе не является полным доказательством эквивалентности произвольного SQL. Многоколоночный NOT IN, корреляция, приведения, нестандартные типы, неизвестные свойства источника оставляются без переписывания. SubPlan сопоставляется по внутреннему источнику; неоднозначность явно сохраняется. Оценочные строки подзапроса не выдаются за число запусков.

## Проверка

- 275 автоматических тестов: 274 успешно, один интеграционный тест пропущен без native PostgreSQL.
- 109 SQL-сценариев: 106 проверены на PostgreSQL 18.6 в PGlite 0.5.12, три параметризованных случая проверены только синтаксически.
- На реальном SQL-движке получен и сопоставлен BitmapOr.
- Для шести кандидатов NOT EXISTS на контрольных данных совпали мультимножества результатов. Это проверка примеров, а не доказательство для всех возможных данных.
- Два контрпримера подтвердили изменение результата при наивной замене с внутренним NULL и при внешнем NULL с пустым подзапросом.
- Есть разные схемы, quoted identifiers, совпадающие псевдонимы, перекрывающиеся ветви OR, корреляция и хорошие запросы.

PGlite исполняет PostgreSQL SQL и каталоги в WebAssembly. Тестовый HTTP-адаптер не проверяет native psycopg, сетевую авторизацию или установку PostgreSQL на macOS. Для этого предусмотрен запуск scripts/run_sql_lab.py в отдельной базе querylens_test*. Весь DDL и тестовые данные откатываются. Не запускать лабораторию в demo или рабочей БД.

## Граница этапа

Синтаксические кандидаты всех 15 правил уже маршрутизируются; углублённая проверка всех 15 ещё не завершена. Следующий этап: DISTINCT, HAVING, CTE и окна, затем измеренный режим, объединённое дерево выводов и экспорт датасета. Диагнозы по одним признакам не являются эталонными метками для обучения LLM.
